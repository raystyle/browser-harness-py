# M105 单测字符串比对路径在 win32 失效

> 分类：测试可移植性。首犯 2026-09-01（Windows 侧复跑 S006 新增的 `/proc` 枚举单测）。

## 现象

`tests/unit/test_browsers.py` 三个用例（NUL 切分 / 空格连接重写 / 无 flag 默认值）在 WSL 全绿，在 Windows 全红——`_chrome_instances_linux()` 返回 `[]`，fixture 的 fake `/proc` 树像没生效一样。[实证: win32 3 failed / 199 passed，Linux 207 全绿（S006）]

## 根因

fixture 拦截 `pathlib.Path.iterdir` 时用**字符串**比对 `str(self) == "/proc"`。win32 上 `Path("/proc")` 归一化为 `\proc`（相对当前盘符），`str()` 出来是 `\\proc`，拦截永不命中 → 生产代码扫真实的 `D:\proc` → `FileNotFoundError`（OSError）→ 防御性返回 `[]`。产品代码行为正确，测试的平台假设错了。

深层原因：S006 的 +10 用例只在 WSL 侧跑过（R004 的共享 `.venv` 陷阱又让 Windows 侧不愿轻易跑套件），单测新增后没有双平台复跑。

## 处理

拦截条件改用 **Path 等值**（PurePath 比较两侧平台各自归一化，win32 上 `/proc` 与 `\proc` 相等）：

```python
if self == pathlib.Path("/proc"):
```

## 预防

- 单测里 patch `pathlib` 时，路径判断一律用 `Path` 对象等值或 `os.fspath` 后的显式双形态判断，禁止裸字符串比对 `Path` 的 `str()`——win32 会改写分隔符与盘符根。
- 涉及平台分支的代码（`/proc`、CIM、platform.system()）新增单测后，至少在另一侧平台跑一遍再收工；共享 checkout 双系统共用时，用 `UV_PROJECT_ENVIRONMENT` 把项目环境引开，避免 .venv 互相重建（R004 陷阱）而不敢跑测试。
