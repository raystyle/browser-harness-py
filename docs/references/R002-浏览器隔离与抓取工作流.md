# R002 浏览器隔离与抓取工作流

> 开发测试参考（要做什么、怎么做）。实证做法来自 S004、S005；本文件是「做什么就按什么流程来」的正确工作流。

## 一、浏览器隔离工作流

> 来源：S004（用户浏览器与 agent 浏览器隔离研究），已实证。

1. agent 用**独立 profile + 独立调试端口**的 Chrome，worker 通过 `BU_CDP_URL` 只连它；用户 Chrome 永不碰。[实证: v0.2.0 独立 Chrome 缩窗、用户 Profile 3 不变]
2. 独立 Chrome 启动参数**不带引号**：`--user-data-dir=...\agent-chrome-profile --remote-debugging-port=9223` + anti-throttle flags。[实证: 带引号曾污染默认 profile，见 M101]
3. 会话复用优先「独立 profile 手动登录一次」；CDP 导出 cookie 会被 Chrome 144+ 默认 profile 的 M144 授权拦住，不推荐。[实证: cookie 导出 ConnectionRefused]
4. 窗口缩窗用 CDP `Browser.setWindowBounds`（分两步：先 windowState=normal 再设 bounds）；Win32 `SetWindowPos` 的 HWND 查找在最大化态不可靠。[实证: S004 尝试 2]

## 二、抓取工作流

> 来源：S005（抓取能力对比）与 web-fetch 增强，已实证。

1. `web-fetch` 公开静态页走纯 HTTP 快路径；遇反爬/登录/JS 页自动升级浏览器（复用会话）。[实证: engine 字段标 `+browser-retry`]
2. 站点专用正文用 `content_selector`（按域名映射，如 github `article.markdown-body`、medium `article`）。[实证: pydefuddle 支持 content_selector]
3. 浏览器抓取用「新开 tab → 抓完关闭」，不 `goto_url` 抢当前 tab，避免污染 X/Google/Bing 的 tab。[实证: 曾多开 Medium/GitHub tab]
4. 正文引擎用 `pydefuddle`（纯 Python）+ bs4 fallback，不依赖 Node/npx。[实证: npx 回退已移除]

## 三、rmux 原子隔离工作流

> 来源：S002 与 rmux 集成，已实证。

1. 所有会话绑固定 label `-L browser-harness`，不与其他程序的 rmux 混用。[实证: kill-server 只清自己 label]
2. `rmux_binary` 优先本机 `AppData\Local\rmux`，不被 PATH 里其它 rmux 干扰。[实证: ohmyagents 的 rmux 未被误用]
3. 幂等启动：`ensure_session`（有则复用，无则新开）；自愈由 supervisor 检测心跳异常后 kill + respawn。[实证: x-monitor 重复调用不重复开]
