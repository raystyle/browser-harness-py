# R003 — 插件开发与测试规范

状态：reference（随 v0.4.0 架构定型）｜适用：`agent-workspace/apps/` 全部插件

## 1. 架构定位

```text
┌─ 薄核心（pip 包，src/browser_harness/）────────────┐
│ daemon / helpers / admin(含 agent Chrome 生命周期) │
│ rmux / browsers / skills / recordings / video      │
└───────────────────────────────────────────────────┘
              │ 引用（只读依赖方向：插件 → 核心）
┌─ 应用层（agent-workspace/apps/，本规范对象）───────┐
│ x-monitor / x-supervisor / x-worker / x-search     │
│ web-fetch / google-search / bing-search            │
└───────────────────────────────────────────────────┘
```

- 数据流（单向）：repo `agent-workspace/apps/`（git 源）→ wheel `references/apps/`（分发母本）→ `skills sync` → workspace `apps/`（运行时）。
- 防漂移：`tests/unit/test_skill_packaged.py` 比对母本与 repo 源，`test_no_app_modules_left_in_package` 禁止应用模块回流包内。

## 2. 插件类型

| 类型 | 形态 | 例 | 退出 |
| --- | --- | --- | --- |
| CLI 型 | 一次性命令，跑完即退 | `x-search`、`web-fetch`、`google/bing-search` | `raise SystemExit(main())` |
| 长跑型 | launcher + rmux 会话（supervisor 自愈 worker） | `x-monitor` | launcher 非阻塞返回 0 |
| 函数型 | `agent_helpers.py` 合并进管道命名空间 | 打包版 agent_helpers | — |

## 3. 开发规范

**命名与入口**
1. 文件名即命令名（kebab-case）：`apps/web-fetch.py` → `browser-harness web-fetch`。
2. CLI 型取参用 `argv = globals().get("APP_ARGS", sys.argv[1:])` —— 既支持 app 路由，也支持直接 `python apps/xxx.py` 调试。
3. **入口禁止 `if __name__ == "__main__"` 守卫**：app 路由是 exec 执行，`__name__` 是 runner 模块名而非 `__main__`，守卫会静默跳过整个入口（v0.4.0 实测踩坑）。统一写 `raise SystemExit(main())`。同理 **`__file__` 在路由下指向 runner** —— 定位同目录文件用 `Path(globals().get("APP_FILE", __file__))`（v0.4.0 实测：x-monitor 用 `__file__` 算 supervisor 路径，指向已删除的包内路径，worker 永远起不来）。
4. 结果走 stdout（人类可读），错误走 stderr 且返回非零退出码。
5. 长跑型：launcher 只负责「启动前置（浏览器/环境）+ `Rmux().ensure_session`」然后返回；业务循环在 worker 里，worker 挂了由 supervisor 重拉。worker/launcher 作为真实脚本被 `python <path>` 调用，`__main__` 守卫可用但非必需。

**环境与连接**
5. 长跑插件在**任何 `browser_harness` import 之前**设 `os.environ.setdefault("BU_NAME", "<app名>")` —— 专属 daemon，不与随手命令抢标签页附着（BU_NAME 是模块导入期读取的）。
6. 浏览器连接交给核心：`.env` 已钉 `BU_CDP_URL=9223`；需要确保 agent Chrome 在跑就 `from browser_harness.admin import _launch_agent_chrome`，**禁止**插件自己拼 Chrome 启动命令（引号坑见 M101）。
7. 插件绝不做浏览器发现/回退 —— `ensure_daemon()` 一把梭，失败信息自然带出。

**数据落位**
8. 一切数据在 `paths.workspace_dir()` 下（db/log/heartbeat）；环境变量覆盖（`X_DB` 式）用 `os.environ.get(...) or` 模式。
9. repo 与 workspace 都不放包内可写状态；包目录只读。

**依赖**
10. 只依赖核心包导出的稳定面（helpers、admin 公共函数、agent_helpers、rmux）与标准库；新三方依赖需评估进 `pyproject.toml`（核心依赖膨胀要慎重，插件不应驱动核心加依赖）。
11. 不引用其他插件的内部；跨插件复用 → 下沉到 `agent_helpers.py` 或核心。

**禁止事项**
12. 不写 `src/browser_harness/`（包只读）。
13. 不碰用户浏览器：守护由 `.env` 钉住 + `ensure_daemon` 只自动启动 9223 端点，插件不得绕过。
14. 不删 workspace 里非自己创建的文件（`skills sync` 同样只增不删）。

## 4. 模板

```python
"""<一句话用途>（workspace app）。

Run:   browser-harness <app名> [args...]
"""
import os
import sys

os.environ.setdefault("BU_NAME", "<app名>")   # 仅长跑型需要


def main() -> int:
    argv = globals().get("APP_ARGS", sys.argv[1:])
    from browser_harness.admin import ensure_daemon

    ensure_daemon()
    # ... 业务 ...
    return 0


raise SystemExit(main())
```

## 5. 测试规范

| 层 | 位置 | 内容 | 门槛 |
| --- | --- | --- | --- |
| 纯逻辑单测 | `tests/unit/test_<app>.py` | 参数解析、DB 查询构造、纯函数；用 `importlib.util.spec_from_file_location` 从 `agent-workspace/apps/` 加载 | 必须有 |
| 防漂移 | `tests/unit/test_skill_packaged.py` | repo apps == 打包 apps；包内无应用模块 | 自动覆盖新插件 |
| 集成验收 | 手册/真机 | CLI 型：每插件 ≥1 条 happy-path 实测；长跑型：`rmux kill` 全栈 → 冷启动 → 心跳 30s 内新鲜 → 数据增长 | 发版前 |
| 行为契约 | SKILL.md | 命令、flag、数据语义变更须同步 SKILL.md 对应章节 | 发版前 |

长跑型验收脚本（x-monitor 为例）：

```powershell
browser-harness rmux kill x-monitor; browser-harness rmux kill x-supervisor
browser-harness --reload
browser-harness x-monitor
# 30 秒内：x_worker.heartbeat 新鲜、x_tweets.db 行数增长、rmux status 两会话存活
```

## 7. 已知边界

- 插件目前随 `skills sync` 铺装 —— 全新安装未跑 sync 时 `browser-harness x-monitor` 报 usage（HELP 有提示）。
- `APP_ARGS` 仅在 app 路由下注入；直接 `python apps/xxx.py` 时回退 `sys.argv[1:]`。
- Windows 优先；跨平台插件自行处理平台分支（参考 x-worker 的 ctypes 空闲检测）。
