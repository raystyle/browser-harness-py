# G002 研究标准细则：结构与六态标记

> 本细则规范 `docs/research/` 的研究、踩坑、实测文档怎么写。本文件落在 `docs/guide/`。
> 新建后须登记 `INDEX.md`。

## 一、角色定位

研究文档回答「为什么这样做、已验证什么、别再踩什么坑」，是方案与决策的事实依据。

| 文档 | 角色 |
| --- | --- |
| `TODO.md` | 当前目标任务进度 |
| `PLAN.md` | 当前目标怎么做 |
| `docs/proven/` | 已完成 plan 的归档 |
| `docs/diary/` | 项目日记（一天一篇，当天总结与自省） |
| `docs/research/` | 本规范对象：研究原型过程 |
| `docs/references/` | 开发测试参考（要做什么怎么做） |
| `INDEX.md`（mistakes 节） | 错误速查 |
| `CHANGELOG.md` / `ROADMAP.md` | 大版本 / 大阶段 |

## 二、何时写

按需即时维护，符合任一即开一篇：踩坑当场沉淀、工具或机制调研、实测记录、多方案对比取舍。

## 三、命名

- 落点：`docs/research/`。
- 文件名等于文档标题：博客式长标题，标点用 `-` 断句，不含空格、括号、冒号。
- 一个主题一篇；写作规范（本文件）落 `docs/guide/`，不进 research 的博客式命名。

## 四、结构模板

必含背景 + 关键结论，按主题取舍其它节。

```markdown
# <与文件名对齐的标题>

> 日期，来源或触发点。

## 背景
## 关键结论
## 现状或实测
## 踩坑沉淀
## 待办
```

## 五、六态标记标准

研究文档的事实性断言（非纯描述 / 指令）须标六态之一，不标即视为未完成。标记与正文同段，用方括号。

| 标记 | 含义 |
| --- | --- |
| `[实证: ...]` | 已在本仓 / 本机实际验证 |
| `[推断: ...]` | 由现象或逻辑推出，未直接验证 |
| `[经验: ...]` | 来自历史惯例，非本次实测 |
| `[记忆: ...]` | 记忆性陈述，建议复核 |
| `[假设: ...]` | 待验证的猜想 |
| `[直觉: ...]` | 主观倾向，非依据 |

用法：断言句尾加 `[实证: <依据>]`；纯描述、命令、引用行可不标；关键结论处必须带标记。禁止把「没验证」写成「已验证」，禁止用猜测冒充结论。
