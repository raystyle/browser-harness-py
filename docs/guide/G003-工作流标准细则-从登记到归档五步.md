# G003 工作流标准细则：从登记到归档五步

> 角色：**元规范**——一个想法从登记到归档怎么走。`PLAN.md` 只留当前目标的计划，通用方法论归此。

## 一、从待办到完成的五步

1. **登记**：新想法进 `TODO.md`（优先级 + 一句话 + 登记日）
2. **立项**：开工前在 `docs/proven/PNNNN-短名.md` 写方案（模板 `docs/guide/template.md`）
3. **执行**：按方案实施步骤推进
4. **验收**：按方案验收标准核对；测试看退出码；文档看清单与断链
5. **归档**：完成后在 `docs/diary/YYYY-MM-DD-*.md` 记当天总结；方案回填「实施过程与经验」；版本级成果记 `CHANGELOG.md`

## 二、拆步骤的标准

- 一步一件事：每个用例只证明一个部件。
- 先方案后代码：部件边界以方案为准。
- 每步带验收：命令退出码 / 测试通过 / 状态符合预期。
- 依赖明确：闸门不满足不开下一步（如无 rmux 不开 rmux 相关功能）。

## 三、优先级与取舍

| 优先级 | 含义 | 处理 |
| --- | --- | --- |
| 高 | 用户点名 / 阻塞其它项 | 先做 |
| 中 | 高项绿了再做 | 排队 |
| 低 | 收尾件 / 明确延后 | 目标末尾或下目标 |

原则：一次只推进一个任务目标（见 `GOAL.md` 锚点）。

## 四、验收的通用口径

- 待办全部已完成或明确跳过（跳过须写 `docs/mistakes/` 原因）。
- 单元测试 `uv run --with pytest python -m pytest tests/unit -q` 通过。
- 新文档已登记 `INDEX.md`；研究与测试文档关键结论标六态。

## 五、过程内自修正循环

五步主流程执行中发现任何问题，就地走闭环：

1. **定位**：搜 `INDEX.md` 与相关文档，确认是否已有规则 / 研究 / 参考覆盖。
2. **归类**：文档错修文档；规则缺补规则；知识缺落研究（六态）；出错记 mistakes（接编 MNNN）；验证过的做法沉淀 references。
3. **修正**：改在源头；下游引用、索引、三原语同步。
4. **验证**：`pytest` + 对账 INDEX 与磁盘。
5. **提交**：一事一提交；diary 记钩子；主线继续。

原则：问题不留在对话或记忆里；不重复造已有规则；临时补丁要么归档成正式资产、要么删掉。
