# 2026-09-02 daemon 单实例守卫

首条 GitHub Issue（#1）驱动的一天：`ome install --force` 停栈前的进程快照抓到同机 **4 个并存 daemon 实例**（2 venv 底座 + 2 裸 python 底座），证实 daemon 无单实例守卫、退出路径不收敛、跨会话累积陈货。

**根因三层**（详见 M109）：ping 一次的守卫有 ~75s TOCTOU 窗口（get_ws_url 30s 死等 + 握手 45s 等弹窗，期间不监听）；Windows 侧临时端口 + `.port` 文件赢家通吃，输家端口号永久丢失变僵尸；PID 文件每次启动覆写，`restart_daemon()` 只能找到最后赢家。

**修复**：内核级单实例锁。POSIX `fcntl.flock` / Windows `msvcrt.locking`，进程死亡 OS 自动释放（无陈锁回收）；锁只盖字节 0、元数据（pid + 解释器路径）写在偏移 1，争抢方零等待可读 holder 身份——LockFileEx 会挡他进程读被锁字节，这个偏移设计是 Windows 侧的关键细节。`daemon __main__` 改为：ping 通（含无锁旧版）→ 退出 0；锁被占 → `BH_LOCK_GRACE`（默认 90s > 合法启动 75s）有界等待，holder 死即接管；超时 → 退出 1 报 holder pid。LOG 截断/PID 写入挪到持锁后，共享文件恢复单写者。

**验证**：+7 单测（锁互斥/跨进程 stdin 信号放锁/claim 三分支），222 全绿；本机 E2E 三分支实测——争抢超时准确报 holder pid、长 grace 无缝接管（日志单写者）、正常生命周期 PID 清理仅留惰性锁文件。TODO 队列「chrome-mode 翻转双拉起竞态」与本条同族，守卫应随之消失，保留观察。

## 自省

- E2E 走了弯路：隔离环境误写 `BU_HOME`（项目前缀是 `BH_`，`BU_` 只有 BU_NAME/BU_CDP_* 家族），三组 daemon 落到真实 runtime 目录的 `bu-guardtest` 名下才发现。好在全程 BU_NAME 隔离 + CDP 不可达，零浏览器接触、零残留，但白跑一轮。教训：隔离变量名先对照 paths.py 再写脚本。
- 跨进程单测首版用 `p.kill()` + 断言 `Popen.pid`：uv run 下 `sys.executable` 是 trampoline，Popen.pid ≠ 持锁解释器 pid，kill 也未必杀得到持锁进程。改为子进程自报 pid + stdin 关闭主动放锁，测试才既真实又稳定。
