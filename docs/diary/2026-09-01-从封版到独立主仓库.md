## WSL2 无头接管（下午追加）

同一天从 Windows 侧切到 WSL 接管（队列目标「Linux/macOS 接管」的 Linux 半）。环境盘点后发现三个硬事实：WSL2 是 mirrored 网络（loopback 与 Windows 互通，9223 直达 Windows 侧 agent Chrome）、WSL 内无 Chrome 且无 snap、launcher 被 Windows checkout smudge 成 CRLF（`bash\r`）。

适配四件套：装 google-chrome-stable .deb（152）、`.gitattributes` 钉 launcher 为 LF、`BH_AGENT_CDP_PORT` 端口可配（WSL 9224 避撞）+ `BH_CHROME_HEADLESS` 无头启动 + `BH_CHROME_EXTRA_FLAGS` 透传、`browsers` 视图补 Linux `/proc` 枚举。

**踩坑 M104**：Linux Chrome 会重写自己的 cmdline 为空格连接，NUL 切分失效，第一版枚举对运行中的 Chrome 返回空。已修 + 单测锁定两种形态。

验证：单测 207 全绿（+10 新用例）、WSL 内 `--doctor` 全绿、web-fetch 浏览器链路实测、`goto_url`/`page_info` 管道自动化实测、`browsers` 正确分类 agent 实例。方案落 S006。遗留：WSL 侧 agent profile 未登录 X，x-monitor 待登录后实跑。

自省：第一版 Linux 枚举只按常规进程 cmdline 形态写，没拿真实 Chrome 验证就上——正是 M104 预防条款写的错误样本。单测里也犯了自己绕 self 的低级错（FakePopen 闭包），好在跑一遍就暴露。
